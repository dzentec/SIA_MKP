## Что строим

Система превращает иллюстрированные морские руководства (PDF/EPUB/DOCX) в локальную базу знаний и предоставляет её ИИ-агентам через протокол MCP. **100 % офлайн, Windows 11.**

Два самостоятельных продукта в одном репозитории:

| Продукт | Роль | Выход |
|---|---|---|
| **`mkp-builder`** | Парсинг → OCR → VLM-аннотация → верификация → чанкинг → триплеты → экспорт | `.bookpack.zip` |
| **`mkp-server`** | Импорт архивов → построение индексов → обслуживание агентов по MCP | Работающая база + MCP-инструменты |

Единица поставки — **одна книга = один `.bookpack.zip`**. Одна база = одна тематика.

---

## Зачем это нужно

Морские руководства богаты иллюстрациями, схемами, таблицами и специальными терминами. Стандартные RAG-системы теряют визуальный контент. Эта система:
- Сохраняет **каждую** фигуру как файл + получает машинное описание через VLM
- Строит **граф знаний** (триплеты сущностей и отношений)
- Предоставляет **гибридный поиск** (dense + BM25 FTS) с RRF-reranking
- Работает полностью **офлайн** после однократной загрузки весов моделей

## Архитектурные принципы (из HLD v1.5)

1. **Артефактная поставка** — между продуктами передаётся только самодостаточный `.bookpack.zip` с манифестом целостности
2. **База на стороне сервера** — индексы строятся только сервером при импорте; билдер индексы не создаёт
3. **Zero Data Loss (визуальный слой)** — каждая иллюстрация сохраняется файлом и получает VLM-описание
4. **Идемпотентность и кэширование** — все LLM/VLM-прогоны кэшируются (ключ: SHA-256 + model + prompt_ver)
5. **Двуязычность** — `lang` на уровне книги/страницы/чанка; мультиязычные эмбеддинги; кросс-языковый поиск RU/EN
6. **Локальность** — транспорт по умолчанию stdio; streamable-http только 127.0.0.1
7. **Blue-green индексация** — MCP продолжает отдавать старую базу во время пересборки

## Контракт артефакта `.bookpack.zip`

```
<book_id>.bookpack.zip
├── bookpack.json          # паспорт (schema_version: "1.5")
├── book_metadata.json
├── pages.jsonl
├── chunks.jsonl           # с полем verification
├── triplets.jsonl         # с provenance
├── qa_review_queue.jsonl  # схемы требующие ручного разбора
└── assets/                # PNG-фигуры
```

## Что «готово» выглядит так

1. `mkp-builder build --book <файл> --profile digital --lang en --out ./out` → создаёт `.bookpack.zip`
2. `mkp-server import <zip> --base C:\marine_base --topic "Морское дело"` → импортирует, строит индексы
3. `mkp-server --base C:\marine_base` → запускает MCP-сервер
4. Агент (Claude Desktop / Open WebUI) подключается и успешно выполняет `search_maritime_knowledge("как взять второй риф на гроте при ветре 25 узлов?")` → возвращает текст + PNG-схему + граф-связи

## Ключевые неизвестные (Phase 0 проверяет)

1. Русская токенизация в LanceDB FTS (default vs ngram)
2. Качество RapidOCR vs Tesseract на кириллице
3. Стабильность VLM qwen2.5vl:7b (JSON-режим, зацикливание)
4. LadybugDB: колёса под Windows/Python 3.11 + реальные Cypher-запросы
5. EPUB-геометрия: карта спайна, привязка фигур
6. Качество e5-large с/без префиксов на RU↔EN парах
